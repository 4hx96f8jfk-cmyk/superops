## 一句话定位

**给你的 AI agent 一本「到底执行过没有」的账本** —— agent 副作用可靠性 + 模型接入治理的运维层。

## 为什么存在（市场证据 2026-11 检索）

- 行业共识：checkpoint 只让 agent「记住」，**不能证明哪条命令跑过、哪封邮件发过、重试会不会重复扣款**
- 从业者实测：繁忙 agent 约 1/4 工具调用可能重复；重复下单/发信/扣款是重大事故区
- 现有玩家空档：Temporal/Restate/DBOS 是基础设施层（必须换运行时引擎）；LangGraph checkpoint 只存状态。**语义层效果对账 + 不要求换框架 = 空白**

## 差异化护城河

1. **语义层对账**：不抢编排，只治理副作用（UNCERTAIN 探测 → 外部真值对账 → CONFIRMED/转人工）
2. **不侵入**：poller/适配器形态，pip 装上就用，agent 框架任选
3. **生产验证**：内部 Avatar 舰队 dogfooding——747 测试、反例夹具、崩溃恢复端到端场景、影子执法误拦率量化（0.00% 实测）
4. **东方哲学仿生进化机制**（内部自进化链的对外叙事名，用于品牌故事层）

## 红线（继承内部治理铁律）

- 控制台**双模式**（运维负责人 2026-11-13 两道令：①「不能只有只读模式，也要有全功能模式，大胆开发，越早出问题越早解决」；②「不要被过度安全问题耽误功能使用，开发测试期功能验证为先」）：**产品默认（superops-cli init/config）为 full**，开放全部写操作（审批裁决/重试/暂停恢复/provider 管理），写路径必须过 effect-ledger 登记 + 审计留痕；**代码工厂 create_app 与独立入口 superops-console 的默认仍为 read-only（安全默认）**，显式配置才放开写；read-only 保留为收紧护栏；绝不建第二调度器
- 探活必须真实推理实测，自报绿≠实际绿
- 密钥永不入库明文；对外文稿禁 AI 腔/营销话术堆砌
