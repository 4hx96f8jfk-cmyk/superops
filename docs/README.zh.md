# HongYun · SuperOps（中文版）

**给你的 AI agent 一本「到底执行过没有」的账本。**

agent 记得自己想干什么，不代表事情真的发生了。SuperOps 是一层专门管「副作用」的运维工具：哪条命令跑过、哪封邮件发出去过、那次重试有没有扣两次钱——账本上写得清清楚楚。

> 对外名称：**HongYun 超级運維智能體 / HongYun Super 運維 Agent**（技术短名 SuperOps），HongYun 旗下独立运维智能体产品线。

## 问题出在哪

checkpoint 让 agent「记住」，但记住不等于证明。

- 2026 年的行业共识：checkpoint 存的是状态，不是执行证据。
- 从业者实测：繁忙的 agent 大约 **每 4 次工具调用就有 1 次可能重复**。重复下单、重复发信、重复扣款，是今年事故最密集的区域。
- 现有方案的空档：Temporal / Restate / DBOS 属于基础设施层，得把工作负载搬进它们的运行时；LangGraph 的 checkpoint 只存状态。**不要求换框架、在语义层做效果对账——这个位置没人占。** SuperOps 就是来占这个位置的。

## 快速开始

> 占位：包正在从生产代码中抽取，即将发布到 PyPI。

```bash
# 即将发布
pip install superops-cli
superops init        # 引导式初始化，默认 SQLite，零外部依赖
```

第一个能跑通的场景：包住一个工具（比如「发邮件」函数），登记副作用，在调用中途把进程杀掉，重启后账本会把 `UNCERTAIN` 的效和对齐外部真实世界——而不是盲目重跑一遍。

## 三个组件

| 组件             | 包名            | 干什么                                                                                                         |
| ---------------- | --------------- | -------------------------------------------------------------------------------------------------------------- |
| **效果账本**     | `effect-ledger` | 副作用登记、幂等键、租约 fencing、`UNCERTAIN` → 对真值核验 → `CONFIRMED` / 转人工、审计事件                    |
| **模型接入管理** | `modelhub`      | 本地 + 云端大模型 provider 注册、真实推理探活（自报绿 ≠ 实际绿）、本地优先路由与回退链、密钥只存引用、用量统计 |
| **运维控制台**   | `ops-console`   | 账本可视化、效果 DAG、鉴权。红线：双模式（full 全功能写 + read-only 收紧护栏），绝不变成第二个调度器           |

## 凭什么不一样

1. **语义层对账。** 不抢编排，只治理副作用：不确定的先探测，拿外部真值核对，确认或转人工。
2. **不侵入。** poller / 适配器形态，pip 装上就用，agent 框架随便你用什么。
3. **生产里滚出来的。** 内部 agent 舰队 dogfooding：747 个测试、反例夹具、崩溃恢复端到端场景，影子执法误拦率实测 0.00%。
4. 设计上承袭 HongYun 的仿生进化机制（东方哲学启发的自进化谱系）——这是品牌故事层的事，不在你的关键路径上。
