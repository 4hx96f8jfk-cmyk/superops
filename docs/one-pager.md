## 定位

**给你的 AI agent 一本「到底执行过没有」的账本。**
agent 副作用可靠性 + 模型接入治理的运维层。不抢编排，只治理副作用。

## 痛点

- checkpoint 让 agent「记住」，但**不能证明**哪条命令跑过、哪封邮件发过、重试会不会重复扣款——记忆不是执行证据
- 从业者实测：繁忙 agent 约 **1/4 工具调用可能重复**；重复下单 / 重复发信 / 重复扣款是 2026 年事故最密集区域
- 空档：Temporal / Restate / DBOS 是基础设施层，必须换运行时；LangGraph checkpoint 只存状态。**语义层效果对账 + 不要求换框架 = 无人占位**

## 三大组件

| 组件         | 包名            | 职责                                                                    |
| ------------ | --------------- | ----------------------------------------------------------------------- |
| 效果账本     | `effect-ledger` | 副作用登记 / 幂等键 / 租约 fencing / UNCERTAIN 对账转人工 / 审计事件    |
| 模型接入管理 | `modelhub`      | provider 注册 / 真实推理探活 / 本地优先回退链 / 密钥只存引用 / 用量统计 |
| 运维控制台   | `ops-console`   | 账本可视化 / DAG / 鉴权；红线：只读 + 白名单命令，绝不建第二调度器      |

## 商业形态

- **开源核心（Apache-2.0）**：`effect-ledger` + `modelhub` 全开源，拉量与建立信任
- **商业版（计划中，未上线）**：多租户控制台 / 合规审计报告导出——等外部信号再启动，不做预约通道表演
